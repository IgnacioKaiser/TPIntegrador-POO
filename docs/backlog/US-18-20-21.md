# US-18 / US-20 / US-21 — Registro CSV e informes

## Qué se implementa

- US-18: cada solicitud XML-RPC válida a nivel de envoltura (incluso rechazada por autenticación) genera una fila `PETICION`; el inicio/cierre y operaciones de conexión generan `EVENTO`.
- US-20: `informe.usuarios` devuelve totales por usuario autenticado, éxitos y rechazos.
- US-21: `log.consultar` muestra registros con filtros y paginación.

Las consultas solo se habilitan al rol `ADMINISTRADOR` en `ServicioProtegido` (no solo en el menú Python).

## CSV

Ruta por defecto: `data/logs/actividad.csv`, relativa al directorio desde el que se inicia el servidor (normalmente raíz del repositorio).

Columnas:

```text
fecha_hora,tipo,id_solicitud,usuario,nodo_cliente,modulo,operacion,codigo,detalle
```

- `fecha_hora`: UTC ISO 8601 (`Z`). El rango de fechas se interpreta en **UTC** e incluye ambos días.
- `tipo`: `PETICION` o `EVENTO`.
- `id_solicitud`: identificador RPC; vacío si no hay solicitud.
- `usuario`: identidad **verificada**; vacío si no se consiguió autenticar.
- `nodo_cliente`: `127.0.0.1` en el servidor actual, que solo escucha en loopback. No representa un nodo remoto si se cambia la configuración.
- `modulo`: origen del registro (`ServidorRPC`, `Robot`, etc.).
- `operacion`: nombre de operación, sin parámetros.
- `codigo`: `OK`, `NO_AUTENTICADO`, `VALIDACION`, etc.
- `detalle`: descripción genérica y segura, nunca contraseñas, contenido G-Code ni parámetros en bruto.

El archivo crece por anexado; no se trunca al reiniciar. Si se utiliza `--db` con otra ruta para pruebas, se usa `actividad.csv` junto a esa base para aislar los datos de prueba.

## Contrato XML-RPC

Ambas operaciones usan el mensaje habitual de **seis campos**, con `credenciales` dentro de `parametros`.

**`informe.usuarios`** — administrador solamente:
- Parámetros opcionales: `usuario` (string), `desde` y `hasta` (string `AAAA-MM-DD`, UTC), `codigo` (string).
- Resultado: `usuarios`: array de structs `{usuario, peticiones, exitosas, rechazadas}`; `total_peticiones`, `total_ok`, `total_errores`: int32.
- Solo cuenta peticiones donde el usuario fue autenticado. Los intentos de ingreso fallidos siguen estando en `log.consultar` sin usuario verificado.

**`log.consultar`** — administrador solamente:
- Filtros opcionales: `usuario`, `desde`, `hasta`, `tipo` (`PETICION` o `EVENTO`), `codigo`.
- Paginación opcional: `offset` (entero >= 0, predeterminado 0), `limite` (entero 1..100, predeterminado 50).
- Resultado: `registros` (array de structs con las nueve columnas), `total`, `offset`, `mostrados` (int32).

Los filtros se combinan por AND. Se devuelven códigos `VALIDACION` para filtros mal formados y `PERMISO_DENEGADO` al operador.

## Comandos desde la raíz (PowerShell)

```powershell
mingw32-make -C server
mingw32-make -C server test
.\server\build\robot_server.exe
```

En otra terminal:

```powershell
python client/main.py ping
python client/main.py eco "Prueba de log"
python client/main.py informe-usuarios --usuario hector --desde 2026-10-01 --hasta 2026-10-31
python client/main.py log --tipo PETICION --desde 2026-10-01 --hasta 2026-10-31
python client/main.py log --codigo NO_AUTENTICADO --limite 20 --offset 0
python client/main.py
```

La CLI pide las credenciales antes de ejecutar cada comando directo. Las nuevas opciones de menú son 19 y 20, visibles solo para administrador.

## Limitaciones conocidas

- Se registran todas las **solicitudes que llegan a `MensajeRPC`**. Si el XML está corrupto y no llega a deserializarse, el protocolo devuelve XML-RPC Fault pero no queda una fila con un usuario identificado (no hay mensaje válido).
- La consulta usa un barrido del CSV; adecuada para el tamaño del TP, no para logs gigantes.
- Se protege la escritura concurrente dentro de un proceso, pero no se soportan dos servidores escribiendo el mismo CSV al mismo tiempo.
- Si hay fallo de disco al registrar una petición, el servidor muestra una advertencia en stderr para no repetir automáticamente movimientos. Ese fallo impide garantizar auditoría completa hasta corregirlo.
- Los reportes cuentan **peticiones**, no sesiones ni movimientos realizados físicamente. La US-19 sigue fuera de alcance.
