# US-24: subir archivos desde el cliente Python

Estado: implementada y verificada en Windows en esta rama; Hito B sin commit/merge.
Fecha: 27/10/2026. Rama: us-15-16-24-tareas. Base: 08b0f4e.
Linux pendiente de ejecucion. No incluye ejecucion de tareas.

## Que pide

Elegir un archivo G-Code local, enviarlo con las credenciales habituales y recibir
una confirmacion de almacenamiento o un error claro. El usuario no elige una cuenta
propietaria ni una ruta de escritura del servidor. Subir no ejecuta el archivo.

## Como funciona y por que

`ServiciosPrueba.subir_archivo(ruta)` usa pathlib (biblioteca estandar de Python)
para comprobar que la ruta es un archivo regular y consultar su tamano antes de
abrirlo. Si supera 1 MiB, no lo lee. La lectura se limita a 1 MiB + 1 byte para
detectar tambien si crecio entre la comprobacion y la lectura. `utf-8-sig` admite
UTF-8 normal o con BOM; una codificacion invalida produce un error local claro.

Luego llama a `subir_tarea(nombre, contenido)`, que agrega credenciales con el metodo
existente `_enviar`. Solo envia el nombre local, sin directorios ni identidad de
otro propietario. `ClienteXmlRpc` usa el transporte existente sin reintentos.
ServicioProtegido autentica y vuelve a validar los datos con RepositorioTareas.
Las decisiones comunes estan en D11/D12 de DECISIONES_DISENO.md y el contrato en
CONTRATO.md; las reglas del archivo se explican en US-15.md.

`CliCliente` ofrece subir y tareas por terminal, ademas de las opciones 17/18 del
menu para operador y administrador. Una lectura fallida no envia ninguna solicitud
de subida. Un rechazo del servidor se muestra con su codigo y mensaje. El menu
puede continuar despues de un error. El listado tiene columnas ID, nombre y
propietario y un mensaje especifico si esta vacio.

## Comandos

Desde la raiz, con servidor iniciado (cambiar puerto si corresponde):

```powershell
python client/main.py --url http://127.0.0.1:8083/RPC2 subir "C:\ruta local\pieza.gcode"
python client/main.py --url http://127.0.0.1:8083/RPC2 tareas
python client/main.py --url http://127.0.0.1:8083/RPC2
```

En Linux usar python3 y una ruta local Linux. Los comandos piden usuario y clave;
no se pasan claves por argumentos ni se guardan archivos de sesion. Una subida
correcta devuelve 0; un error devuelve 1. Una respuesta perdida deja el resultado
sin confirmar: consultar tareas permite revisar si el archivo llego. No se reintenta.

## Prueba manual breve con dos operadores y un administrador

En una primera terminal PowerShell, desde la raiz, preparar una instalacion temporal:

```powershell
mingw32-make -C server
$pruebaTareas = Join-Path $env:TEMP ("poo-tareas-" + [guid]::NewGuid().ToString("N"))
.\server\build\usuarios_admin.exe inicializar --db "$pruebaTareas\usuarios.sqlite"
.\server\build\usuarios_admin.exe agregar --db "$pruebaTareas\usuarios.sqlite"
.\server\build\usuarios_admin.exe agregar --db "$pruebaTareas\usuarios.sqlite"
.\server\build\robot_server.exe --db "$pruebaTareas\usuarios.sqlite" --tareas-dir "$pruebaTareas\tareas" --port 8083
```

Elegir el administrador al inicializar y los operadores ana y bruno al agregar.
Usar claves de prueba al solicitarlas, sin escribirlas en los comandos.
El servidor crea las carpetas necesarias y queda esperando en esa terminal.

En otra terminal, desde la misma raiz, crear un archivo de prueba y subirlo:

```powershell
$archivoTarea = Join-Path $env:TEMP ("pieza-" + [guid]::NewGuid().ToString("N") + ".nc")
Set-Content -LiteralPath $archivoTarea -Encoding utf8 -Value "G90`nM114"
python client/main.py --url http://127.0.0.1:8083/RPC2 subir $archivoTarea
python client/main.py --url http://127.0.0.1:8083/RPC2 tareas
```

Ingresar ana en esas dos consultas: debe ver su tarea. Consultar como bruno antes
de subir: debe ver lista vacia. Subir el mismo archivo como bruno y listar: vera su
propia tarea, con otro ID. Listar como administrador: vera ambas con sus propietarios.
Volver a subir como ana debe devolver ESTADO_INVALIDO, sin sobrescribir.
No se necesita Arduino; no se envia G90 ni M114 al robot al subir ese archivo.
Detener con Ctrl+C en la terminal del servidor. Conservar juntos la base temporal
y su carpeta de tareas si se quiere revisar la prueba despues.

En Linux el recorrido equivalente usa make, python3, ejecutables sin .exe y un
directorio creado con mktemp -d; las mismas opciones --db y --tareas-dir permiten
mantenerlo aislado. Es una instruccion de uso, no una verificacion Linux realizada.

## Pruebas ejecutadas y limites

`mingw32-make -C server test` paso en Windows nativo/MSYS2 UCRT64 con g++ 15.2.0 y
Python 3.14.0: dominio, usuarios, autenticacion, 59 comprobaciones de almacenamiento,
43 pruebas del cliente y 32 de integracion real con C++. No se ejecuto Linux.

Las pruebas de cliente en test_tareas.py usan archivos temporales y respuestas
simuladas: lectura BOM, tamano antes de abrir, lectura acotada, errores locales,
comandos, ambos menus, lista vacia/formato de filas, rechazos y timeout sin reintento.
La integracion ejecuta la CLI Python contra el servidor real con bases y carpetas
temporales explicitas; verifica contenido en disco y listado tras reiniciar C++.
Tambien verifica propiedad, duplicados, parametros invalidos, autenticacion,
cuenta deshabilitada y cuatro subidas concurrentes al mismo nombre. Un espia C++
confirma que tareas no invoca ServicioRobot. Los logs no incluyen contenido de prueba.

Las dos pruebas de enlaces simbolicos del Hito A siguen omitidas en este entorno
por permisos/plataforma. No se simularon disco lleno ni corte de energia. No se
agregan descarga, edicion, borrado, ejecucion automatica, informes ni cambios de firmware.
