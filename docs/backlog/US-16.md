# US-16: listar tareas respetando la propiedad

Estado: listado local y RPC con cliente implementados y verificados en Windows.
Fecha: 27/10/2026. Rama: us-15-16-24-tareas. Base del Hito B: 08b0f4e.
Sin merge a master; pruebas en Linux pendientes.

## Que pide y como se resuelve

Los criterios de US-16 dicen que OPERADOR ve solo sus archivos y ADMINISTRADOR
puede ver todos. Cada tarea debe poder identificarse sin ambiguedad.

`RepositorioTareas::listar(const Usuario&)` recorre solo la carpeta del operador o
todas las carpetas numericas de propietario para el administrador. Devuelve un
vector de Tarea, ordenado por propietario_id y nombre, sin cargar ni mostrar el
contenido. Cada registro tiene un identificador como `2:pieza.gcode`; dos archivos
llamados pieza.gcode de propietarios diferentes tienen identificadores distintos.
Un administrador ve tambien sus propios archivos. Sin tareas se devuelve una lista vacia.

No se listan temporales, subdirectorios internos, enlaces ni archivos con nombres
que no pertenezcan al formato administrado. Una carpeta de operador que es un
enlace o un archivo se rechaza; el listado global no recorre enlaces de directorio.
Un fallo de lectura produce ErrorTarea de tipo ALMACENAMIENTO, no una lista vacia
que parezca indicar ausencia de tareas.

El Usuario es una precondicion de la API local: en Hito B viene de Autenticador.
No hay un parametro con el que el cliente pueda elegir consultar otra carpeta.
El repositorio rechaza un Usuario deshabilitado o con identidad/rol invalidos;
ServicioProtegido ademas verifica las credenciales y habilitacion en cada solicitud RPC.

## Decisiones y conceptos

`std::vector` es la coleccion de resultados y `std::filesystem::directory_iterator`
permite recorrer directorios sin depender de comandos de Windows o Linux. Son
parte de C++17. Las decisiones de almacenamiento y sus alternativas estan en D11
de DECISIONES_DISENO.md. Las reglas de contenido y escritura se explican en US-15.md.
No se agregan indices en SQLite ni se duplican metadatos persistentes.

## Pruebas y limites

Ejecutar desde la raiz `mingw32-make -C server test-tareas` en Windows o
`make -C server test-tareas` en Linux. El mismo test usa directorios temporales.

En Windows se comprobaron lista vacia, visibilidad con dos operadores y un
administrador, mismo nombre entre propietarios distintos, orden estable,
persistencia despues de reabrir y temporales ignorados. Los datos Usuario son
objetos de prueba; no se crean cuentas reales ni se verifica una clave en este hito.
Los casos con enlaces se omiten si la plataforma no permite crearlos; en esta
ejecucion Windows los omitio. Linux no se ejecuto.

Base de usuarios y carpetas de tareas deben conservarse juntas para mantener la
asociacion por ID. No se verifico el mismo bloque en Linux.

## Hito B: listado remoto

`tarea.listar` no acepta parametros adicionales a las credenciales. Despues de
autenticar, ServicioProtegido llama al repositorio y resuelve el nombre de cada
propietario con RepositorioUsuarios. No duplica esos nombres en archivos ni agrega
una tabla. Devuelve una lista de id, nombre y propietario, sin rutas ni contenido.
Si encuentra una carpeta de un ID sin usuario en la base, informa ERROR_INTERNO;
no puede detectar que un ID haya sido reutilizado. Por eso el respaldo conjunto
sigue siendo necesario. El contrato exacto se mantiene en CONTRATO.md.

`ServiciosPrueba.listar_tareas()` construye el pedido autenticado. `CliCliente`
muestra filas con ID, nombre y propietario, o un mensaje claro de lista vacia.
Se puede usar el comando tareas o la opcion 18 del menu de ambos perfiles. El
cliente no permite elegir otro propietario; si alguien arma ese parametro por
fuera de la consola, el servidor lo rechaza como VALIDACION.

La suite completa de Windows paso: 43 pruebas simuladas de cliente, 32 de
integracion con servidor C++ real, almacenamiento y pruebas C++ existentes.
La integracion comprueba dos operadores aislados, administrador viendo los tres
propietarios (incluido el administrador), identificadores distintos con nombres
iguales, lista vacia, consulta por CLI, cuenta deshabilitada y parametros adicionales.
Las pruebas usan bases y carpetas temporales; no se accede a datos reales.
Para el recorrido manual con esos perfiles ver US-24.md.
