# US-05: habilitar y deshabilitar operadores

## Alcance

Un usuario con rol `ADMINISTRADOR` puede habilitar o deshabilitar cuentas `OPERADOR`
mediante el cliente Python y el metodo XML-RPC `robot.intercambiar`.
La cuenta del administrador inicial no puede ser habilitada ni deshabilitada por esta operacion.
No se eliminan usuarios, no se cambian contrasenas ni roles.

## Contrato de las operaciones

Los mensajes mantienen exactamente seis campos: `id`, `tipo`, `operacion`,
`parametros`, `resultado` y `codigo`. Las credenciales se envian en todas las solicitudes,
dentro de `parametros.credenciales` (estructura con `usuario` y `clave`).

| Operacion | Parametro adicional | Respuesta satisfactoria |
|---|---|---|
| `usuario.habilitar` | `usuario`: string, nombre del operador | `resultado.usuario` string, `resultado.habilitado` boolean `true`, `resultado.mensaje` string |
| `usuario.deshabilitar` | `usuario`: string, nombre del operador | `resultado.usuario` string, `resultado.habilitado` boolean `false`, `resultado.mensaje` string |

Codigos de error:

- `NO_AUTENTICADO`: credenciales incorrectas o inexistentes.
- `PERMISO_DENEGADO`: solicitante no administrador, cuenta solicitante deshabilitada o intento de modificar el administrador.
- `VALIDACION`: parametros ausentes, inesperados o con tipos incorrectos.
- `RECURSO_NO_ENCONTRADO`: nombre de usuario inexistente.
- `ERROR_INTERNO`: fallo de persistencia.

## Responsabilidades

1. `ServiciosPrueba` (Python) construye la solicitud.
2. `ServicioProtegido` (C++) autentica y comprueba el rol administrativo.
3. `RepositorioUsuarios` actualiza exclusivamente usuarios de rol `OPERADOR` mediante SQLite.
4. El servidor devuelve una respuesta con el mismo `id` y la misma `operacion`.
5. Una cuenta deshabilitada queda bloqueada en la siguiente solicitud, ya que `Autenticador` consulta el estado en cada mensaje.

Los cambios son idempotentes: repetir habilitar una cuenta habilitada o deshabilitar una cuenta deshabilitada devuelve `OK` y mantiene el estado. El cliente no debe reintentar automaticamente ante un corte de comunicacion.

## Pruebas

Desde la raiz del repositorio en Windows:

```powershell
mingw32-make -C server
mingw32-make -C server test
```

Las pruebas automatizadas usan bases temporales. Para pruebas manuales conservar la base real ya inicializada y tener el servidor corriendo en otra terminal:

```powershell
python client/main.py deshabilitar operador
python client/main.py habilitar operador
```

Cada operacion solicita las credenciales del actor. El servidor, no la CLI, controla los permisos.
