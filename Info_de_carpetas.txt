# Organización del proyecto integrador

## 1. Objetivo de esta organización

Este documento define la estructura de carpetas del trabajo integrador y establece qué tipo de archivos debe contener cada una. El objetivo es que todos los integrantes trabajemos con la misma organización, evitemos duplicar archivos y podamos integrar nuestros aportes sin interferir con el trabajo de los demás.

El proyecto se organiza alrededor de tres componentes principales:

- **Servidor en C++:** recibe solicitudes mediante XML-RPC, valida las operaciones solicitadas y coordina las acciones del sistema.
- **Cliente en Python:** permite que el usuario interactúe con el servidor desde una interfaz de línea de comandos. Esta interfaz podrá ampliarse posteriormente.
- **Firmware de Arduino:** controla el hardware del robot. Se utiliza el firmware proporcionado por la cátedra, conservándolo completo y sin modificaciones, salvo que la consigna o el equipo docente indiquen lo contrario.

También se contemplan carpetas para almacenar datos, registrar la actividad del sistema y documentar su funcionamiento.

## 2. Estructura general

La estructura de trabajo es la siguiente:

```text
TP_integrador_real/
├── server/
│   ├── xmlrpc/
│   ├── include/
│   ├── src/
│   └── Makefile
├── client/
├── firmware/
│   └── arduino/
├── data/
│   ├── db/
│   ├── logs/
│   └── trayectorias/
├── docs/
├── README.md
└── .gitignore
```

Esta estructura establece una separación entre los componentes del sistema. Los nombres de los archivos concretos podrán definirse a medida que avance la implementación, pero se debe mantener la separación de responsabilidades.

## 3. Servidor: `server/`

En esta carpeta se encuentra el código del servidor desarrollado en C++. Su responsabilidad es procesar las solicitudes recibidas, ejecutar la lógica correspondiente, comunicarse con el robot y devolver resultados al cliente.

### `server/xmlrpc/`

Contiene la biblioteca de XML-RPC en C++ utilizada para implementar la comunicación entre el cliente y el servidor. Los archivos de esta biblioteca provienen del trabajo anterior de XML-RPC.

Se debe conservar la estructura interna de la biblioteca y sus archivos relacionados. No conviene mezclar su implementación con las clases propias del trabajo integrador, ya que esto dificultaría distinguir el código de terceros del código desarrollado por el grupo.

### `server/include/`

Contiene los archivos de cabecera propios del servidor, generalmente archivos `.h` o `.hpp`.

Aquí se declaran las clases, sus atributos, sus métodos y las interfaces que necesitan conocer otros componentes del programa.

Por ejemplo, si se implementan clases como `Robot`, `Usuario`, `ControladorRobot` o `GestorUsuarios`, sus declaraciones podrán ubicarse en esta carpeta.

### `server/src/`

Contiene los archivos fuente `.cpp` correspondientes a las clases y funciones propias del servidor.

Aquí se implementará la lógica del sistema: la administración de usuarios, la validación de permisos, el procesamiento de las solicitudes XML-RPC, la coordinación del robot y la gestión de errores.

El archivo `main.cpp` del servidor también se ubicará aquí. Será el punto de entrada del programa y se encargará de inicializar los componentes necesarios y poner en funcionamiento el servidor.

### `server/Makefile`

Contiene las instrucciones de compilación del servidor y de los archivos C++ que necesita.

La compilación debe contemplar tanto el código propio como los archivos necesarios de la biblioteca XML-RPC. La estructura definitiva de las instrucciones de compilación se establecerá cuando se integre el código.

## 4. Cliente: `client/`

Contiene el código desarrollado en Python para que el usuario interactúe con el sistema y envíe solicitudes al servidor.

El cliente y el servidor son programas independientes: el cliente solicita operaciones y el servidor las procesa. No se debe implementar en el cliente la lógica que corresponde exclusivamente al servidor, como la validación definitiva de permisos o la ejecución de acciones sobre el robot.

Como organización inicial, se proponen los siguientes archivos:

- `main.py`: punto de entrada del cliente.
- `interfaz_cli.py`: administra la interacción con el usuario mediante la terminal, por ejemplo, mostrando opciones y leyendo comandos.
- `cliente_rpc.py`: reúne las funciones necesarias para conectarse al servidor mediante XML-RPC e invocar sus métodos.
- `modelos.py`: puede contener las clases o estructuras que el cliente necesite para representar solicitudes, respuestas u otros datos intercambiados.

Estos nombres son una propuesta inicial. Se podrán ajustar cuando se defina el diseño definitivo, manteniendo la separación entre interfaz de usuario, comunicación y representación de datos.

El cliente puede utilizar la biblioteca estándar de Python para XML-RPC, por lo que no es necesario instalar una biblioteca externa únicamente para realizar estas llamadas.

## 5. Firmware: `firmware/arduino/`

Contiene el firmware de Arduino proporcionado por la cátedra.

Se debe copiar o conservar **la carpeta completa del firmware original**, incluyendo el archivo `.ino` y todos los archivos adicionales que este incluya o necesite para compilar.

No se debe copiar solamente el archivo `.ino`, ya que podría depender de otros archivos. Tampoco se deben modificar arbitrariamente sus nombres, rutas relativas o instrucciones
